What is Clustering?

Discovering similarity structures in unlabeled data — the unsupervised side of machine learning.

Core Idea

Cluster analysis discovers similarity structures in datasets — the resulting group assignment is called clustering.

Unlike regression and classification, clustering belongs to unsupervised learning.

Two principles for similarity

  • Distance-based — e.g., K-Means uses Euclidean distance to centroids
  • Density-based — e.g., DBSCAN groups dense neighborhoods

Where clustering shows up

  • Industry Anomaly detection in condition monitoring
  • CV Pattern recognition in image processing
  • Pre-processing Clustering can serve as a pre-sorting step, providing a starting point for labeling data points into classes
Supervised vs. Unsupervised. Supervised learning learns a mapping x → y from labeled pairs. Unsupervised learning sees only x and must find structure on its own.

K-Means Algorithm

One of the most widely used clustering methods — straightforward to describe and easy to implement.

The algorithm — four steps

The algorithm searches for cluster centers that represent distinct regions within the data. It divides N unlabeled data points into a predefined number of K clusters.

1

Initialise

Select randomly K data points as the initial centroids c1, …, cK.

2

Assign each data point xi to the nearest centroid ck

This forms K clusters Ck where k ∈ {1, 2, …, K}. A data point xi belongs to cluster Ck if:

xi ∈ Ck  if  k = arg mink ‖xi − ck‖²

where ‖xi − ck‖² is the squared Euclidean distance between the data point and the centroid.

3

Update each cluster centroid

Move each centroid to the average of all data points assigned to its cluster Ck:

ck = 1|Ck|  ∑xi ∈ Ck xi

|Ck| is the number of data points in cluster j.

4

Convergence check — repeat 2 and 3

Repeat steps 2 and 3 until the centroids no longer change significantly, meaning the difference between centroid positions in two consecutive iterations is zero or falls below a small tolerance (threshold).

Cost Function & the Elbow Method

K-Means minimises a cost. Plotting cost against K gives the elbow.

The optimisation objective

The optimisation objective of K-Means is to minimise the cost function J, defined as the sum of squared distances between each data point and its assigned centroid:

J = N∑i=1 K∑k=1 ‖xi − ck‖² · 𝟙{xi ∈ Ck}

The average of this cost function over the number of data points is called distortion.

  • Each iteration refines the centroid positions to reduce both the cost function and the distortion
  • When the cost function changes only insignificantly, the centroids have stabilised
  • In the worked example, the cost flattens after iteration 2, consistent with the centroid convergence observed earlier

The elbow method — choosing K

The algorithm requires the number of clusters K to be specified in advance, but it is often not known.

To identify a suitable number of clusters, the cost function is plotted as a function of K. The resulting graph resembles an elbow:

  • At K = 1 the cost is highest and decreases with increasing K
  • The optimal K is chosen at the point where the curve transitions from a steep drop to a roughly linear, flat decline — the "elbow"
  • A different K yields a different result — with K = 2, for example, the converged cost is higher, since two centroids cannot capture the structure as well as three
  • In the classic example, K = 3 represents the suitable number of clusters
Adding more centroids always reduces J (with K = N, J = 0). The elbow method identifies the point where adding another cluster no longer yields a meaningful reduction in J — trading fit quality against model complexity.

K-Means++ — Smarter Initialisation

K-Means++ chooses starting centroids more carefully: first random, then far-apart points with high probability based on squared distance.

Why initialisation matters

K-Means does not optimise the centroid positions globally. It starts from initial centroids and then improves them step by step. Because of that, the starting points strongly affect the final result.

  • If two initial centroids start in the same natural cluster, K-Means may waste iterations fixing that poor start
  • Bad initialisation can lead to a higher final cost J even after convergence
  • Different random starts can produce different clusterings on the same dataset
  • Practitioners often run K-Means multiple times and keep the solution with the lowest cost
Main problem: ordinary random initialisation can place centroids too close together. K-Means++ reduces this risk.

Core idea of K-Means++

K-Means++ still starts randomly, but after the first centroid it prefers points that are far from the already chosen centroids.

  • c1 is chosen uniformly at random from the data points
  • For every remaining point, compute its squared distance to the nearest chosen centroid
  • Points with larger D² receive larger selection probability
  • This tends to place one initial centroid in each natural region of the dataset
Important: K-Means++ does not directly choose the farthest point by distance alone. It uses a probability distribution based on D². The worked example below follows the argmax interpretation: the point with the highest probability is selected as the next centroid.

K-Means++ step by step

1

Choose the first centroid randomly

Select one data point uniformly at random and call it c1.

2

Compute the nearest-centroid squared distance

For each point xi, compute

D²(xi) = minj ‖xi − cj‖²

This means: look at all already chosen centroids and keep only the squared distance to the nearest one.

3

Convert distances into probabilities

Normalise all D² values:

P(xi) = D²(xi)N∑j=1 D²(xj)

Large D² means large probability. Points already chosen as centroids have D² = 0 and therefore probability 0.

4

Choose the next centroid and repeat

Select the next centroid from this probability distribution. In the worked example below, the point with the highest probability (argmax) is chosen. Continue until K initial centroids are selected.

Why do we use squared distance?

  • Squaring gives even more weight to points that are very far away
  • This makes isolated or distant regions more likely to receive their own centroid
  • The same squared Euclidean distance is also used later in the standard K-Means cost function

Why the minimum distance?

  • If a point is already close to one chosen centroid, it does not need another nearby centroid
  • Using the minimum distance avoids repeatedly placing centroids in the same region
  • This is exactly why, in the PDF example, points near B or F get small probabilities when choosing c3

Silhouette Analysis

A score in [−1, 1] that measures how well each point fits its cluster — and whether clusters are well-separated.

The Silhouette Coefficient

In practice, the ideal number of clusters is often unknown. The ideal value ensures that:

  • Cohesion — points are arranged closely to each other within a cluster
  • Separation — different clusters are well distinguishable from each other

To determine the best K, the Silhouette Coefficient can be used. For each data point xi, two parameters are calculated:

a(i) = mean distance from xi to all other points in its own cluster
b(i) = mean distance from xi to all points in the nearest other cluster
S(i) = b(i) − a(i)max{a(i), b(i)}

For the illustrated lecture example: a(i) ≈ 0.88, nearest-cluster distance b(i) ≈ 2.95 ⇒ Silhouette Coefficient ≈ 0.70.

Interpreting the value

  • S(i) close to +1 — the sample is well clustered
  • S(i) close to 0 — the sample is on or very close to the decision boundary between neighboring clusters
  • S(i) close to −1 — the sample might have been assigned to the wrong cluster
The overall silhouette score for the dataset is the mean Silhouette Coefficient across all data points. The thickness of each band in the silhouette plot reflects the cluster size.

Overall silhouette score — interpretation

Overall Silhouette ScoreInterpretation
0.71 – 1.00A well-defined, strong clustering structure
0.51 – 0.70A reasonable clustering structure with good separation
0.26 – 0.50A weak structure
< 0.25Little to no underlying clustering structure

In the lecture example the overall silhouette score is 0.72, which falls just into the well-defined range.

When K-Means Fails

The Euclidean distance assumption shapes — and limits — the algorithm.

Distance measure affects cluster formation

K-Means forms clusters based on the distance to the centroids, which affects the formation of clusters. This causes problems in several situations:

  • Different spatial extent — using distance causes some sample values to be assigned differently than expected
  • Standardisation can reduce but not fully eliminate this effect; principal component analysis of the features can also help
  • Two-moon samples may not be recognised as contiguous clusters by Euclidean distance assessment
  • Other clustering methods are needed — for example DBSCAN, which takes a fundamentally different approach: instead of measuring distance to centroids, it forms clusters based on local density

New data points

When a new data point arrives, the algorithm would in principle need to be rerun on the entire dataset to redetermine the clusters.

  • However, if the existing sample size N is large, a single new point will have little effect on the cluster structure
  • In that case, the new point can be provisionally assigned to the nearest existing centroid — deferring a full rerun of K-Means until it becomes necessary

Two failure modes — live

K-Means is fit (with K = 2) on two pathological shapes. Watch how it slices Euclidean half-planes through clusters that look obvious to a human.

Take-away. K-Means partitions space with linear (Voronoi) boundaries between centroids. It works well for compact, spherical, similar-size clusters — and poorly for everything else. The next section introduces DBSCAN, which clusters by density rather than distance to a center.

DBSCAN — Density-Based Spatial Clustering of Applications with Noise

Find dense neighborhoods of arbitrary shape — and identify outliers — without specifying K.

Core idea

  • DBSCAN takes a fundamentally different approach: instead of measuring distance to centroids, it forms clusters based on local density
  • The number of clusters does not need to be specified in advance
  • Can recognise complex cluster structures (rings, moons, ribbons)
  • Can be used to identify outliers
  • The algorithm checks whether and which data points lie within the ε-neighborhood of other data points
  • Evaluation of an ε-neighborhood around each data point
  • Classification into core, border and noise points depending on the number of data points within the ε-neighborhood

Two hyperparameters

  • ε — the radius of the neighborhood
  • KMIN — the minimum number of points required to qualify as a core point

Point classification

The same point can be core, border, or noise — it depends only on how many points fall inside its ε-circle. Example below uses KMIN = 4.

C

Core point

Has at least KMIN points (including itself) within its ε-neighborhood.

B

Border point

Has fewer than KMIN points in its own ε-neighborhood, but lies within the ε-neighborhood of a core point.

N

Noise point (outlier)

Has fewer than KMIN points in its own ε-neighborhood and is not within the ε-neighborhood of any core point (not reachable).

Classification procedure

1

Starting from a core point

Label all points within its ε-neighborhood as border points belonging to the same cluster.

2

Check whether each of these points is itself a core point

If so, expand the cluster through its neighbours.

3

Repeat until all points have been classified

Points that no core point can reach remain as outliers (noise points).

Lecture example. With KMIN = 5: three clusters are formed. One point has no other data points within its ε-neighborhood and is classified as an outlier.

DBSCAN — Choosing ε and KMIN

Parameter studies of ε and KMIN reveal how cluster count and outlier rate respond.

Estimating ε from a distance histogram

Reasonable values for ε can be estimated by examining the pairwise distances between all data points:

  • These distances are represented as a histogram
  • The key is to identify the smallest distance at which a significant proportion of point pairs occurs
  • In the lecture example, only about 2 % of all pairwise distances are 0.2 or less
  • ε should be chosen slightly above this range to capture meaningful local density without merging distant regions
  • Further fine-tuning (optimisation) of ε is done through parameter studies

How ε and KMIN change the result

Increasing ε

  • The proportion of outliers decreases because each point's neighborhood covers a larger area, making it more likely to contain at least KMIN points
  • The number of clusters initially increases because more points meet the KMIN threshold and form their own small clusters
  • As ε continues to increase, nearby clusters merge into larger ones — the number of clusters decreases

Increasing KMIN

The clustering result depends on KMIN for a given ε. If KMIN is reduced, the density requirement becomes less strict — groups of points previously classified as outliers now form their own clusters.

  • The higher KMIN is, the stricter the density requirement — fewer points qualify as core points, making it harder to form clusters
  • The proportion of outliers increases with increasing KMIN
  • With higher KMIN, only denser regions survive as clusters — smaller, sparser clusters dissolve, so the remaining clusters tend to be larger but fewer in number

Lecture example: KMIN = 5 → 3 clusters, 28 outliers. KMIN = 3 → 5 clusters, 13 outliers.

3. Silhouette Analysis — GridSearchCV

Use scikit-learn's GridSearchCV with a custom silhouette scorer. The custom CV split uses the full dataset for both training and evaluation (unsupervised setting).

# Define a custom scorer using silhouette_score
def cv_silhouette_scorer(estimator, X):
    estimator.fit(X)
    cluster_labels = estimator.labels_
    num_labels = len(set(cluster_labels))-(1 if -1 in cluster_labels else 0)
    num_samples = X.shape[0]
    if num_labels == 1 or num_labels == num_samples:
        return -1
    else:
        return sc(X, cluster_labels)

# Define the parameter grid
param_grid = {'n_clusters': np.arange(2, 11)}

# Define the custom CV split as provided
cv_splits = [(np.arange(len(X_scaled)), np.arange(len(X_scaled)))] # fixed CV

# Use GridSearchCV with the custom scorer and custom CV split
grid_search = GridSearchCV(estimator=KMeans(random_state=42, init='k-means++'),
                           param_grid=param_grid,
                           scoring=cv_silhouette_scorer,
                           cv=cv_splits,
                           n_jobs=-1)

# Fit the model
grid_search.fit(X_scaled)

# Get the best number of clusters
best_k = grid_search.best_params_['n_clusters']
best_score = grid_search.best_score_
labels = grid_search.best_estimator_.labels_
centroids = grid_search.best_estimator_.cluster_centers_

print(f'Best number of clusters (k): {best_k}')
print(f'Best silhouette score: {best_score:.3f}')

# Results for all k values
results = pd.DataFrame(grid_search.cv_results_)

# Show clusters and the centroids in the original range of the features
plt.figure(figsize=(10, 6))
unique_labels = set(labels)
colors = plt.cm.Spectral(np.linspace(0, 1, len(unique_labels)))

for k, col in zip(unique_labels, colors):
    if k == -1:
        col = 'k'  # Black used for noise.
        label = 'Outliers'
    else:
        label = f'Cluster {k}'

    plt.scatter(X[(labels == k), 0], X[(labels == k), 1], color=col,
                edgecolor='k', s=50, label=label)

# scatter the centroids
centroids_viz = scaler.inverse_transform(centroids)[:, :2]
plt.scatter(centroids_viz[:, 0], centroids_viz[:, 1], c='orange',
            edgecolor='k', s=200, marker='X', label='Centroids')

plt.title(f'K-Means Clustering with k={best_k}')
plt.xlabel('Sepal Length')
plt.ylabel('Sepal Width')
plt.legend()
plt.show()

4. DBSCAN — Manual Grid Search

Generate ε × kmin combinations with numpy.meshgrid, run DBSCAN for each, and record outliers, cluster count, and silhouette score.

# Generate an array of combinations for hyperparameters epsilon and kmin
eps = np.arange(0.2, 1.5, 0.2)
kmin = np.arange(2, 6, 2)
EPS, KMIN = np.meshgrid(eps, kmin)
outlier = np.zeros(EPS.shape)
cluster_numbers = np.zeros(EPS.shape)
silhouette_scores = np.zeros(EPS.shape)

# Gridsearch For-Loops
for m in range(eps.shape[0]):
    for n in range(kmin.shape[0]):
        db = DBSCAN(min_samples=KMIN[n, m], eps=EPS[n, m],
                    metric='euclidean').fit(X_scaled)
        labels = db.labels_
        outlier[n, m] = list(labels).count(-1)
        cluster_numbers[n, m] = len(set(labels)) - (1 if -1 in labels else 0)

        if cluster_numbers[n, m] > 1:
            sil_score = sc(X_scaled, labels)
        else:
            sil_score = -1  # Invalid silhouette score

        silhouette_scores[n, m] = sil_score

# Find the maximum silhouette score and the corresponding parameters
max_sil_score = np.max(silhouette_scores)
max_index = np.unravel_index(silhouette_scores.argmax(), silhouette_scores.shape)
best_eps = EPS[max_index]
best_kmin = KMIN[max_index]
best_outlier = outlier[max_index]
best_cluster_number = cluster_numbers[max_index]

print(f'Max silhouette score: {max_sil_score:.3f}')
print(f'Best eps: {best_eps:.2f}')
print(f'Best kmin: {best_kmin}')
print(f'Number of clusters: {best_cluster_number}')
print(f'Number of outliers: {best_outlier}')

7. Choosing the Range of ε

Compute pairwise distances and plot relative frequency — the distance at 2 % relative frequency gives a lower bound for a reasonable ε range.

# Distances for all combinations of points
diff = (X_scaled[np.newaxis, :, :] - X_scaled[:, np.newaxis, :])

dist = pd.Series(np.sqrt((diff**2).sum(axis=2)).reshape(-1))

# Define the classes and calculate relative frequencies.
# 0.1 represents the resolution that classifies the distances into classes
classes = np.arange(0, dist.max()+0.1, 0.1)
frequency_rel = dist.value_counts(normalize=True, sort=False, bins=classes)
frequency_rel.iloc[0] = 0

# Plot the relative frequency
fig, ax1 = plt.subplots(figsize=(7, 5))
ax1.bar(classes[0:-1] + 0.1, frequency_rel * 100, width=0.2)
ax1.set_xlabel("Distance d")
ax1.set_ylabel("Relative Frequency h(d) / %")

# Annotate the point where relative frequency equals 2%
# and add a vertical line
threshold = 2.0
for i, freq in enumerate(frequency_rel):
    if freq * 100 >= threshold:
        ax1.axvline(x=classes[i], color='r', linestyle='--',
                    label=f'2% threshold at d={classes[i]:.1f}')
        break

plt.legend()
plt.tight_layout()
plt.show()
Rule of thumb. About 2 % of point-pairs have a distance ≤ 0.5. The ε search range (0.2 – 1.5) is chosen slightly above this threshold.

Formula Reference

K-Means

Assignment:   xi ∈ Cj ⇔ j = arg minj ‖xi − cj‖²
Update:   cj = 1|Cj| ∑xi ∈ Cj xi
Cost:   J = N∑i=1 ‖xi − ca(i)‖²   where a(i) is the assigned cluster
Distortion:   D = J / N

K-Means++

Choose c1 uniformly at random from the data. Choose ck from the data with probability proportional to D(x)² — where D(x) is the distance from x to its nearest already-chosen center.

Silhouette Coefficient

S(i) = b(i) − a(i)max{a(i), b(i)}
  • a(i) — mean distance from xi to the other points in its own cluster (intra-cluster)
  • b(i) — mean distance from xi to the points of the nearest other cluster
  • Range: [−1, 1]. Overall score = mean S(i) over all points.

DBSCAN

  • ε — neighborhood radius
  • KMIN — minimum number of points (including the point itself) for a core point
  • x is a core point if |Nε(x)| ≥ KMIN
  • x is a border point if it is in the ε-neighborhood of a core point but is not itself a core point
  • x is a noise point (outlier) if it is neither core nor border
