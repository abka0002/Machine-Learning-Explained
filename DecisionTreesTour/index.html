Decision Trees: Rules from Data

A decision tree is a supervised, non-parametric, model-based learner. It carves up the feature space with a sequence of if/else rules, producing a structure that is fast to evaluate and (within reason) directly readable by humans.

Eager What "eager" means here

  • Model-Based Learning: a tree is constructed during training by recursively splitting the dataset on feature values.
  • Non-Parametric: the structure adapts to the data — depth and branching grow as needed.
  • Interpretability: the resulting tree is a sequence of human-readable if/else rules.
  • Versatile: classification trees and regression trees share the same recursive logic.

The CART training recipe

  1. Start at the root with all training samples.
  2. For every (feature, threshold) candidate, compute the impurity reduction Δ — using Gini (or entropy) for classification and variance / MSE for regression.
  3. Pick the split with the largest Δ and partition the data into two children.
  4. Recurse on each child until a stopping criterion is met (pure / zero-variance leaf, min samples, max depth).
The same recipe handles both tasks — only the impurity measure and the leaf output change: a classification leaf predicts the majority class, a regression leaf the mean target. Three ideas drive everything that follows: impurity (Gini / variance), greedy recursive splitting, and complexity control (pruning). The next four tabs unpack each one.

Decision Trees · Gini Impurity

Gini impurity measures how often a randomly chosen element would be incorrectly labelled if it were labelled randomly according to the distribution of labels in the set. It is zero when a node is pure, and maximal when classes are perfectly mixed.

The formula

GI = KΣi=1 pi(1 − pi) = 1 − KΣi=1 pi2

pi: relative frequency of class i (the proportion of instances in class i).

  • Minimum (zero): all samples in the node have the same label — the node is pure.
  • Maximum: all K classes are equally likely: pi = 1/K, giving GImax = 1 − 1/K.
  • For binary classification (K = 2), the maximum is 0.5; for K = 3 it is 0.667; for K = 4 it is 0.75.

Why the maximum is 1 − 1/K

For K classes, find the proportions pi that maximise GI = 1 − Σ pi² subject to Σ pi = 1.

Every pi is equal at the maximum impurity, so pi = 1/K. Plug back:

GImax = 1 − K · (1/K)² = 1 − 1/K

So for K = 2 → 0.5; K = 3 → 0.667; K = 10 → 0.9. The metric does not have the same range for all problems — keep this in mind when comparing trees trained on datasets with different numbers of classes.

Tree terminology

  • Root Node: the top node that represents the entire dataset and provides the first decision rule.
  • Internal Nodes: intermediate nodes that apply decision rules to further split the data.
  • Leaf / Terminal / End Nodes: the final nodes that give the prediction.
  • Parent / Left Child / Right Child: a node's "Yes" branch is the left child; its "No" branch is the right child.

Stopping criteria

  • The split does not reduce impurity by more than the threshold (minimum impurity decrease).
  • The node contains fewer samples than the minimum required to split.
  • No further features are available for splitting.
  • The node is pure (only one class present) — it becomes a leaf.

Feature Importance

For each split, the impurity reduction indicates how much that node contributed to the decision. Summing those reductions per feature, then normalising, gives the feature importance.

Split impurity reduction

ΔGI(s) = Wparent · GIparent − ( Wleft · GIleft + Wright · GIright )
  • ΔGI(s) is the impurity reduction at split s.
  • Wparent, Wleft, Wright are the fractions (weights) of samples in the parent, left child and right child nodes.

Aggregate & normalise

AI(xm) = Σs ∈ S(xm) ΔGI(s)
Importance(xm) = AI(xm) MΣi=1 AI(xi) → all importances sum to 1.

Calculations

Why the importances sum to 1

Two complementary facts make the normalisation work:

  1. Weighted ΔGI telescopes. Summing Wnode·GInode−ΣWchild·GIchild over all internal nodes collapses to GIroot − ΣWleaf·GIleaf.
  2. If every leaf is pure (as in the Go_for_walk tree), each GIleaf = 0, so the total reduction equals GIroot = 0.48 exactly.

That is why 0.137 + 0.343 = 0.48 — the denominator in the normalisation is the root Gini itself. After dividing, the importances necessarily sum to 1.

Overfitting and Pruning

An unconstrained decision tree grows until every leaf is pure — perfect training accuracy, but poor generalisation. Pruning controls complexity by limiting tree growth or trimming branches after construction.

Pre-pruning (early stopping)

Limits are set on the tree's growth, such as:

  • Maximum depth of the tree
  • Minimum number of samples required to split a node
  • Minimum impurity decrease required to make a split

Pro: fast — stops splits before they happen. Con: a node that looks unsplittable now might have led to an excellent split two levels down (the "horizon effect"). Pre-pruning can miss those.

Post-pruning (after construction)

The tree is first grown to its maximum size, then branches with little contribution are removed. Pro: the algorithm sees the full picture before deciding what to keep. Con: more expensive than pre-pruning, and most methods need a held-out set.

Three common techniques — Reduced Error Pruning (REP) - Cost Complexity Pruning (CCP, weakest-link pruning) - Minimum Error Pruning (MEP)

Regression Trees

A regression tree uses the same greedy recursive splitting as a classification tree — but the target is a continuous number, not a class. Two things change: the impurity measure becomes variance (or MSE) instead of Gini, and each leaf predicts the mean of the samples that fall into it. The result is a piecewise-constant step function.

What changes vs. classification

ClassificationRegression
Targetclass labelcontinuous value
ImpurityGini / entropyvariance (MSE)
Split scoreΔGiniweighted MSE reduction
Leaf outputmajority classmean of leaf samples
Leaf prediction: ŷ = (1/n) Σi yi
Node MSE: MSE = (1/n) Σi (yi − ŷ)²

n = the number of training samples that fall in that node; yi = their target values (here, prices); ŷ = the node's prediction, which is the mean of those yi. So a node's MSE is just the average squared distance of its samples from their own mean — the variance of the prices inside it.

The split chosen at each node is the one that minimises the weighted MSE of the two children — exactly analogous to maximising ΔGini.

A real-world example, step by step: house prices

Here is a concrete problem. We have 12 houses; each row is a living area (m²) and its sale price (k€). We want a tree that predicts price from area. Watch it build one split at a time, and follow the MSE arithmetic at every node.

The dataset · 12 houses

#Area (m²)Price (k€)

Mean price = 263.9 k€. A tree that ignored area would predict this for every house — its MSE is the root MSE = 11 710 (k€²). Each split lowers that.

Why a tree here?

Price clearly rises with area, but not on a perfectly straight line — small flats, mid-size homes, and large/premium houses each sit in their own band. A regression tree carves the area axis into those bands and predicts the average price of each band.

The prediction for a house is read off in one step: find which area-interval it falls in, output that leaf's mean price. No equation, no slope — just a lookup table the tree discovered on its own.

The unit of MSE here is k€² (price is in k€, error is squared). Its square root, the RMSE, is back in k€ and tells you the typical prediction error in money.

Why a step function?

Each leaf owns an interval of the input space and predicts a single constant — the mean of its training targets. Because the prediction is constant within a leaf and jumps at every split boundary, a regression tree can never produce a smooth or sloped line. It approximates a curve with a staircase.

More depth ⇒ more leaves ⇒ finer steps ⇒ lower training MSE — but past a point the steps start tracking noise rather than signal, the same overfitting story as classification. This is exactly why random forests (next tab) average many trees: a single deep regression tree is high-variance.

Random Forest

A single deep tree overfits — it has low bias but high variance. A random forest trains many decorrelated trees on different bootstrap samples and combines them. Averaging cancels the variance, keeping the bias low. Explore the three ideas below: the ensemble, bagging, and the scikit-learn implementation.

1 · The ensemble idea

Ensemble What a random forest is

  • An ensemble of many decision trees whose predictions are combined — typically far more accurate and robust than any single tree.
  • Each tree is trained on its own random bootstrap sample of the training data (bagging).
  • At each split, only a random subset of features is considered, which decorrelates the trees.
  • Predictions are aggregated by majority vote for classification and by averaging for regression.
  • Why it works: averaging many decorrelated trees lowers variance with little added bias, mitigating the overfitting of single deep trees.

2 · Bagging = Bootstrap Aggregating

Bagging is a two-stage procedure — not just sampling

The word bagging is a contraction of Bootstrap Aggregating. Bootstrap sampling alone is only the first half: it gives you a collection of independently trained trees. It is the aggregation step that turns them into one prediction and is what actually reduces variance.

Stage 1 — Bootstrap
Draw B independent samples of size N with replacement from the training data; train one tree on each.
Stage 2 — Aggregate
Combine all B tree outputs: majority vote for classification, average for regression → one final prediction.
Press Run to watch the two stages animate: first each tree draws its own bootstrap sample (notice records repeat — sampling with replacement), then the trees vote and the votes are aggregated into one prediction.
A random forest is bagging plus one extra twist: at every split only a random subset of features is considered. Plain bagging keeps all features at each split; the feature subsetting is what further decorrelates the trees so the aggregation reduces variance even more.

Stage 1 details · the bootstrap sample

  • For every tree, a separate training subset — the bootstrap sample — is drawn from the original data with replacement.
  • If the original set has N records, the algorithm draws N records at random, so every bootstrap sample has the same size as the original.
  • With replacement means each selected record is returned to the pool before the next draw, so it can be picked again.
  • Consequently, some records appear several times in a sample while others do not appear at all.
  • The records left out of a tree's sample are its Out-of-Bag (OOB) records — on average about one third (≈ 37%) of the data per tree.
Stage 2 — the aggregation/majority-vote mechanic — is visualised live in the forest classifier demo at the top of this tab: each tree casts a vote and the tally decides the final class.

Each draw leaves a different set of records out. Average the OOB fraction over many draws and it settles near 36.8%.

Important: OOB is per‑tree, not global — no data is wasted

A common misconception is that out-of-bag records are never used in training. They are. Each tree draws its own independent bootstrap sample, so a record left out of one tree is almost certainly in the samples of many other trees.

For any record and any single tree:
P(in‑bag for that tree) ≈ 63%  →  trains that tree
P(OOB for that tree) ≈ 37%  →  that tree never sees it

Over a forest of, say, 500 trees, one record is in‑bag for ≈ 316 trees and OOB for ≈ 184. It helps build the large majority of the forest — it is only "unseen" by the ≈ 37% of trees that happened to exclude it.

Why this makes the OOB score honest: to predict record i, scikit‑learn aggregates votes from only the trees for which i was OOB. Those trees genuinely never trained on i, so their combined prediction is unbiased for it. Repeat for every record and average → an unbiased generalisation estimate, even though every record trained most of the forest.
  • "Are OOB items unused in training?" — No. They train ≈ 63% of the trees.
  • "Are they used within some tree's bootstrap anyway?" — Yes, virtually always — just not in every tree.

Why ≈ 37 %? The probability a record is never picked

In one bootstrap draw of N records, the chance a specific record is not chosen on a single pick is (1 − 1/N). Across all N independent picks:

P(record is OOB) = ( 1 − 1N)N  ⟶  1e ≈ 0.3679  as N → ∞
(1 − 1/16)16 = 0.3561  →  in-bag ≈ 0.6439

Even for small N the OOB fraction is already close to 1/e. It approaches the limit very quickly.

Solid curve: (1 − 1/N)N. Dashed line: the asymptote 1/e. Dot: your N.

Key points

  • scikit-learn reference — RandomForestClassifier.
  • Enable bootstrap sampling with bootstrap=True (this is the scikit-learn default).
  • Out-of-bag (OOB) error: the OOB records act as a built-in validation set, giving an unbiased estimate of generalisation performance without a separate hold-out.
  • Obtain the OOB estimate by setting oob_score=True (requires bootstrap=True).
  • Key hyperparameters & trade-off: tune n_estimators, max_features, and tree size (max_depth / min_samples_leaf); the model is more accurate and stable than a single tree, but no longer easily interpretable.
Because every tree has its own ≈37% of unseen OOB records, scikit-learn can score each sample using only the trees that never saw it, then average — yielding the OOB estimate essentially for free.

Typical usage with an OOB estimate

from sklearn.ensemble import RandomForestClassifier clf = RandomForestClassifier( n_estimators=100, max_features='sqrt', bootstrap=True, # default oob_score=True, # requires bootstrap=True random_state=42, n_jobs=-1, ) clf.fit(X_train, y_train) # unbiased generalisation estimate from out-of-bag records print("OOB score:", clf.oob_score_) print("Test acc :", clf.score(X_test, y_test))

Tuning the forest with GridSearchCV

Same idea as the max_depth grid search on the Overfitting & Pruning tab, but now over several random-forest hyperparameters at once. GridSearchCV trains the model for every combination in the grid, scores each with k-fold cross-validation, and refits the winning configuration on the full training set.

from sklearn.ensemble import RandomForestClassifier from sklearn.model_selection import GridSearchCV param_grid = { 'n_estimators': [100, 300, 500], 'max_depth': [None, 10, 20], 'max_features': ['sqrt', 'log2'], 'min_samples_leaf': [1, 2, 4], } grid = GridSearchCV( estimator=RandomForestClassifier( random_state=42, n_jobs=-1), param_grid=param_grid, cv=5, # 5-fold cross-validation scoring='accuracy', refit=True, # refit best params on full train set n_jobs=-1, ) grid.fit(X_train, y_train) print("Best params:", grid.best_params_) print("Best CV :", grid.best_score_) print("Test acc :", grid.best_estimator_.score(X_test, y_test))

How big is this grid?

3 × 3 × 2 × 3 = 54 combinations
× 5 CV folds = 270 forest fits

The grid grows multiplicatively — adding one parameter with 4 options here would quadruple the work. Keep grids small and coarse first, then refine around the best region.

Scaling alternatives

  • RandomizedSearchCV — sample a fixed number of random combinations instead of all of them; far cheaper for large grids.
  • HalvingGridSearchCV — successive halving: many candidates on little data, then fewer candidates on more data.
  • OOB score — for a forest specifically, oob_score_ is a built-in validation estimate with no extra refitting, useful for a quick sweep of n_estimators before a full grid search.
Tip: use grid.cv_results_ (a dict you can load into a DataFrame) to inspect the mean/std CV score of every configuration, not just the winner.
