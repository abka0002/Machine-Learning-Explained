K-Nearest Neighbors: The Lazy Learner

KNN is a supervised, non-parametric, instance-based algorithm. It builds no model during training — it simply stores the data and answers every query by inspecting the k closest points in the feature space.

Lazy What "lazy" means here

  • Instance-Based Learning: no model is constructed during training.
  • Storage of Instances: the algorithm simply stores all training data.
  • On-Demand Computation: the work happens at prediction time — distances are computed, neighbors are found, votes are tallied.
  • Non-Parametric: no fixed parameter set; expressiveness grows with the data.
  • Versatile: works for both classification (vote) and regression (average).

The four-step recipe at prediction time

  1. Choose the number of neighbors k.
  2. Compute the distance between the query and every training point.
  3. Identify the k closest training points.
  4. Classification: predict the majority class. Regression: predict the mean of the neighbor targets.
Three knobs control the algorithm: the distance metric, the value of k, and the weighting scheme. The next four tabs explore each one with interactive demos.

Why standardisation matters (and matters a lot)

Every distance metric on this slide treats features symmetrically — but features measured in different units are not symmetric:

Imagine two features: age (years, range 0–80) and salary (€, range 0–100 000).
A 1-year difference contributes |Δ| = 1; a 1 €/yr salary difference also contributes |Δ| = 1.
Salary's variance swamps age's contribution by a factor of ~104.

Standard practice: apply StandardScaler (subtract mean, divide by std) or MinMaxScaler before fitting KNN. This is not optional — it can change predictions dramatically.

Practice Practical tips for applying KNN

  • Always scale features first. KNN is distance-based, so a feature on a larger numeric range dominates the metric. Standardise (z-score) or min–max scale inside a Pipeline so scaling is refit on every CV fold and never leaks test statistics.[1]
  • Select k by cross-validation. Small k → low bias / high variance (jagged boundary); large k → high bias / low variance. Tune k with k-fold CV rather than a single split.[1,2]
  • Prefer odd k (binary) or distance weighting. Odd k avoids tied votes; the distance-weighted rule wi = 1/di breaks ties naturally and is more robust where sample density varies.[3]
  • Mind the curse of dimensionality. In high d the contrast between nearest and farthest neighbours vanishes, so plain KNN degrades. Reduce dimensionality (PCA, feature selection) or learn a metric before applying KNN.[4,5,6]
  • Match the metric to the data. Euclidean for continuous, roughly isotropic features; Manhattan for robustness to outliers; fractional / large-p Minkowski can behave very differently in high-dimensional spaces — test it.[5]
  • Handle class imbalance. Plain majority voting is biased toward frequent classes — combine with resampling or class-aware weighting and report per-class precision/recall, not just accuracy.

How to calculate the distances?

Assume a dataset with m features. The distance between two points X1 = (x11, …, x1m) and X2 = (x21, …, x2m) can be computed with several metrics. Drag the two points to see how each distance changes.

Euclidean (p=2) Manhattan (p=1) Minkowski Chebyshev (p→∞)

1. Euclidean Distance

deuclidean(X1, X2) = √mΣi=1(x1i − x2i)2

2. Manhattan Distance

dmanhattan(X1, X2) = mΣi=1|x1i − x2i|

3. Minkowski Distance (parameterised)

dminkowski(X1, X2, p) = (mΣi=1|x1i − x2i|p)1/p
  • For p=1, it reduces to Manhattan.
  • For p=2, it reduces to Euclidean.
  • For p→∞, it becomes Chebyshev: maxi(|x1i − x2i|).

Current distances — step by step

Note: Selecting a suitable distance metric can improve KNN performance significantly — especially when features are on different scales or correlated.

Why Chebyshev is the limit of Minkowski as p → ∞

Increase the p slider above and watch the orange Minkowski value converge toward the purple Chebyshev value. This is not a numerical coincidence — it follows from a short proof:

Step 1 — Define. Let ai = |x1i − x2i| be the absolute difference along each feature, and let amax = maxi ai be the largest of them.

Step 2 — Factor out amax.

(mΣi=1aip)1/p = amax · (mΣi=1(ai / amax)p)1/p

Step 3 — Take p → ∞. Every ratio ai / amax lies in [0, 1]. When raised to a huge power p:

  • Ratios strictly < 1 → 0 (e.g. 0.8100 ≈ 2 × 10−10)
  • Ratios equal to 1 → 1

So the inner sum collapses to the count of maximisers (at most m), and the outer 1/p drives any finite number → 1. The entire bracket → 1.

limp→∞ dMink(p) = amax · 1 = maxi |x1i − x2i| = dChebyshev

Intuition: what happens visually?

As p grows, the Minkowski "unit ball" (the set of points at distance ≤ 1) morphs from a diamond (p=1) through a circle (p=2) into a square (p→∞). The distance cares less and less about all features except the single one with the biggest gap — which is exactly what max does.

Try it: Set the slider to p = 1, then slowly drag it upward. The orange Minkowski path on the canvas approaches the purple Chebyshev line, but the rate depends on the two points: if one coordinate gap dominates the other, the two values match by p ≈ 5–10; if both gaps are similar, you need p ≈ 50 or more before they agree to within a percent (e.g. at equal differences in 2D, Minkowski/Chebyshev = 21/p, which is still 1.15 at p = 5).

And as p → 0?

As p shrinks below 1, the distance becomes increasingly "additive" — sensitive to many small differences. But for p < 1 the Minkowski function is not a true metric.

In practice, p ∈ {1, 2} covers nearly all KNN tasks. Larger p emphasises the single most-differing feature; p < 1 is theoretically interesting but rarely used.

💡 Other Distance Metrics Worth Knowing

Beyond the four Minkowski-family metrics above, several other distance functions are commonly used in machine learning — each suited to specific data types:

MetricFormula / ideaTypical use case
Cosine distance1 − cos(θ) = 1 − (X1 · X2) / (‖X1‖ ‖X2‖)Text / NLP (TF-IDF, embeddings) — measures angle, ignores magnitude.
Hamming distanceCount of positions where symbols differCategorical features, binary strings, error detection in coding theory.
Jaccard distance1 − |A ∩ B| / |A ∪ B|Set-based data — e.g. document similarity, recommendation systems.
Mahalanobis distance√[(X1−X2)⊤ Σ−1 (X1−X2)]Correlated features — accounts for covariance structure automatically.
Haversine distanceGreat-circle distance on a sphereGeospatial data — latitude/longitude coordinates.

In scikit-learn, custom metrics can be passed via the metric parameter of KNeighborsClassifier (e.g. metric='cosine', metric='minkowski' with p=3), or a user-defined callable.

Reading the curves

  • k = 1: training error is exactly 0 — each training point is its own nearest neighbor. Validation error is at its highest: the model memorises noise.
  • Small k (3–5): jagged boundaries with islands around outliers. Low bias, high variance.
  • Moderate k: boundaries smooth out and validation error reaches its minimum — the sweet spot. For the active strategy, the minimum is at k* = 10 with mean CV accuracy ≈ 0.9692.
  • Large k (k → N): the model predicts the global majority class everywhere. High bias, low variance; validation error rises again.
  • The two curves are not a single train/val split — each point is the average over the 5 CV folds.

Three search strategies, three answers

An even k like 10 can yield tied votes in binary classification (e.g. 5 vs 5 of the 10 neighbours). The lecture suggests two ways to eliminate this risk: (a) restrict the grid to odd k, or (b) keep all k but switch to distance-weighted voting so the closer neighbour breaks the tie naturally. The three rows below come from running the same GridSearchCV protocol with each param_grid and weights setting.

Takeaway: "the optimal k" depends on your search space and your weighting scheme. With uniform weights and all integer k, the lecture's grid search returns k = 10 — an even number that risks ties. Restricting to odd k gives k = 9; switching to weights='distance' on the full grid gives k = 12. All three are close in CV accuracy; the choice is a methodological one, not a numerical one.

Python code: GridSearchCV with KNN

The code below replicates the lecture's 5-fold CV experiment. Two key hints are embedded in comments: (1) using odd values for k to avoid tied votes in binary classification, and (2) applying the weights='distance' argument to weight neighbors by inverse distance, which naturally breaks ties when k is even. 

import numpy as np
import pandas as pd
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, GridSearchCV, StratifiedKFold
from sklearn.neighbors import KNeighborsClassifier
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline
from sklearn.metrics import classification_report, confusion_matrix
import matplotlib.pyplot as plt

# Load breast cancer dataset
data = load_breast_cancer()
X, y = data.data, data.target

# Split the data into training and test sets (80/20 split, stratified)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.20, stratify=y, random_state=42
)

# Initialize a pipeline for KNN classifier
# HINT 1: weights='uniform' treats all neighbors equally
# HINT 2: weights='distance' weights neighbors by 1/distance, breaking ties naturally
pipe_knn = Pipeline([
    ('scaler', StandardScaler()),
    ('knn', KNeighborsClassifier(p=2, weights='uniform'))  # p=2 → Euclidean distance
])

# Define the range of k values to search
# STRATEGY 1: All k from 1 to 20
n_k = 20
param_grid = {'knn__n_neighbors': range(1, n_k+1, 1)}

# STRATEGY 2: Only ODD k values (avoids tied votes in binary classification)
# Uncomment the line below to use only odd k:
# param_grid = {'knn__n_neighbors': range(1, n_k+1, 2)}  # 1, 3, 5, ..., 19

# STRATEGY 3: All k with distance weighting
# To use distance weighting, modify the pipeline above:
# ('knn', KNeighborsClassifier(p=2, weights='distance'))

# Perform grid search with Stratified K-Fold cross-validation
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=42)
grid_search = GridSearchCV(
    pipe_knn, param_grid, cv=cv, 
    scoring='accuracy', 
    return_train_score=True
)
grid_search.fit(X_train, y_train)

# Get the mean test scores and training scores
mean_test_scores = grid_search.cv_results_['mean_test_score']
mean_train_scores = grid_search.cv_results_['mean_train_score']

# Plot training and validation classification error
plt.figure(figsize=(8, 6))
plt.plot(range(1, n_k+1, 1), 1-mean_train_scores, marker='o', 
         label='Mean Training Classification Error')
plt.plot(range(1, n_k+1, 1), 1-mean_test_scores, marker='o', 
         label='Mean Validation Classification Error')
plt.xlabel('Number of Neighbors (k)')
plt.ylabel('Classification Error')
plt.title('Effect of k on Classification Error (GridSearchCV)', fontsize=10)
plt.legend(fontsize=9)
plt.grid(True)
plt.xticks(range(1, n_k+1))
plt.show()

# Best hyperparameters
print("Best parameters:", grid_search.best_params_)
print("Best CV accuracy:", grid_search.best_score_)

# Evaluate on test set
y_pred_test = grid_search.predict(X_test)
print("\nTest set Confusion Matrix:")
print(confusion_matrix(y_test, y_pred_test))
print("\nClassification Report (test set):")
print(classification_report(y_test, y_pred_test))
Key concepts highlighted in the code:
  • Odd k values (Strategy 2): By setting param_grid = {'knn__n_neighbors': range(1, n_k+1, 2)}, you search only odd k (1, 3, 5, ..., 19). This eliminates the risk of tied votes in binary classification, since an odd number of neighbors can never split 50-50.
  • Distance weighting (Strategy 3): Setting weights='distance' in KNeighborsClassifier assigns higher weight to closer neighbors (weight = 1/distance). This naturally breaks ties when k is even: the closer neighbor wins. It also tends to produce smoother decision boundaries than uniform weighting.
  • Pipeline structure: The Pipeline ensures that StandardScaler is fit only on the training folds during cross-validation, preventing data leakage. This is critical for honest CV scores.
  • StratifiedKFold: Maintains the class distribution in each fold, important for imbalanced datasets.

Distance Weighting in KNN

By default, every neighbor counts equally (uniform). With distance weighting, closer neighbors carry more influence — useful when data is unevenly distributed or when ties are possible. Drag the blue test point and compare predictions side-by-side.

Uniform weighting

All neighbors contribute equally to the prediction. This is the default setting in scikit-learn.

Classification: ŷ = mode(y1, …, yk)
Regression: ŷ = 1k kΣi=1 yi

Distance weighting

Each neighbor is weighted by wi = 1/di, where di is the distance to the test point.

Classification: ŷ = argmaxc kΣi=1 wi · 𝟙(yi = c)
Regression: ŷ = kΣi=1 yi/di kΣi=1 1/di

# Class di 1/di wi·yi

The regression formula, derived

For regression, the distance-weighted prediction is a weighted average with weights wi = 1/di:

ŷ = kΣi=1 wi yi kΣi=1 wi = kΣi=1 yi / di kΣi=1 1 / di
  • Why divide? Without the denominator, predictions would explode whenever the query coincided with a training point (1/d → ∞). The denominator normalises the weights to sum to 1, keeping ŷ in the convex hull of the neighbor labels.
  • Edge case di = 0 (query equals a training point): both numerator and denominator diverge, but sklearn handles this by returning the matching label exactly.
  • Other weight kernels are possible: Gaussian (wi = exp(−di²/σ²)), tri-cube, etc. The 1/d form is sklearn's default weights='distance'.
